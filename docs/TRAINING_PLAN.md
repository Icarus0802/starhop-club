# 121 孔中国跳棋：真实策略／价值训练方案

核验日期：2026-10-10。本文是可执行的研发计划，**不是训练完成报告**。当前正式 1.3.0 的 AI 仍是人工评价、Fast PVS／团队规划搜索；没有加载神经网络权重。PR、搜索优化、手写评价参数和训练后的模型权重是四种不同交付物。

本轮只读取项目、公开源码与模型元信息，没有安装训练框架、下载新模型、运行训练或占用正在进行的等时自战测试。后续每个训练阶段都应独立记录是否实际完成。

## 1. 当前结构性缺陷

源码依据：`js/fast-search.js`、`js/ai.js`、`js/team-planner.js`；实战依据：`docs/benchmarks/USER_GAME_95.md`、两盘大师留出棋谱。以下结论针对当前正式快照，不把尚未通过测试的实验候选说成正式版行为。

| 缺口 | 实际影响 | 可学习的对象 |
|---|---|---|
| 几何最小分配、距离平方、入营数量是评价的主要部分 | 同样的几何进度可能有完全不同的接力条件；先入营多不代表全队先完成 | 由完整后续实战结果学习局面价值，而不是把几何分数改名为胜率 |
| 当前 Fast 的运输项只检查首跳，距营不超过两格时略过运输项 | 低估完整长链，也忽略近营后子与剩余空孔不匹配的调整成本 | 完整合法连跳生成、空孔结构、桥梁依赖和后子运输；网络输入及辅助题保留真实占位 |
| 相邻己子数量近似桥梁价值 | 邻近棋子不一定有空落点；撤掉关键一子可能让其他后子改走多手 | 走法后的全队与对方路线变化、最终胜负；不将固定棋形当通用定理 |
| 350ms 下依靠浅层选择搜索和几何排序 | 跨多个自方回合的搭桥／撤桥／装填容易越过搜索视野；LMR 也会减少靠后走法的考察 | 策略网络改善根和内部排序，价值网络估计较远期结果；仍须等时检验 |
| 自战主要对旧版，局数小、开局少 | 容易只学会胜过一个弱对手，或者参数对本次堵塞棋谱过拟合 | 多版本对手池、独立开局、完整败局与循环记录、最后封存的验收组 |
| 没有经结果校准的模型 | 界面趋势分数不能当真实胜率；当前“挑战”名称没有冠军对局证据 | 留出集校准、可靠性曲线、未知标记，之后再考虑展示概率 |

用户这盘第 35、41、43 手的占点切断了实际跳路；第 67、71 手则展示成组桥梁运输。第 66 手双方入营数为红 3、绿 2，不支持“从开局每个阶段都被碾压”。第 70 手实战没有防住接力，旧核在另一轮默认 350ms 测量中能找到 H7→H6，不能据此称旧核绝无防守能力。实战思考预算未记录，时延与缓存会影响完成深度。

终盘两颗红子需要五手最短冻结收官，双方累计完成步差为四手；这是 `scripts/frozen-completion.cjs` 已证明的特定冻结局面运输量。**不是一般局面的真实剩余步数标签，也不是继续双边对战的必然结果。**

## 2. 可用外部资源重新核验

仍未找到同时满足“121 孔、双人十子传统单跳、可取得权重、明确 MIT／Apache 类分发许可”的即插即用强模型。这个结论是本轮搜索结果，不是断言世界上没有其他模型。

本项目已保留的 `vendor/upstream` 只有原 MIT 星形棋盘／Alpha-Beta 参考，来源、固定提交和署名在 `THIRD_PARTY.md`。它不是神经网络教师，也不含已训练权重。本轮不引入其他 vendor。

策略／价值自战方法参考 [AlphaZero 原始论文](https://arxiv.org/abs/1712.01815)；论文证明的是其报道的棋种和实验，本项目不能借用其棋力结论。浏览器推理可用 [ONNX Runtime Web 官方接口](https://onnxruntime.ai/docs/tutorials/web/)；运行时是 [MIT](https://github.com/microsoft/onnxruntime/blob/main/LICENSE)，不代表其加载的任意第三方模型也获得 MIT 许可。

## 3. 先固定一个训练任务

第一阶段只做 **121 孔／双人／每方十子／短跳／目标营不锁定／首次满营获胜**，与当前用户对局一致。合法连跳可以在任意合法终点停止，每次完整连续跳只算一手；所有四个侧角保留。三次重复与 600 手上限按当前共享规则和对局调度统一终止；有合法走法不能 pass。

长跳、目标营锁定、多玩家、QQ 等回合完成和反堵塞变体各有 `rulesId`，不能混用终局标签。先训练一个经验证的双人短跳网络，再以单独任务或规则特征扩展；扩展前须有同规则测试。

训练环境初版由一个持久 Node 规则进程提供批量 JSONL 请求，不每手新建进程。只使用 `E.legalMoves`、`E.applyMove` 与同一重复／终局调度；Python负责张量和优化。若后续用 C++ 加速，必须在初始、实战、随机合法轨迹上逐状态对照完整合法端点集合、下一棋盘、终局；不得因加速裁掉后退、侧角或已入营棋子的合法撤出。

### 动作和局面契约

- 动作 ID 为 `from * 121 + to`，共 14,641 个端点位置，合法掩码来自完整规则枚举。每个 from→to 是一手；不把连跳拆成多个独立回合。相同端点的多条路径产生相同最终棋盘，策略合并到同一 ID，显示和落子时再取规则层规范路径。
- 不使用“第几颗棋子”作为永久语义。棋子无身份，排序变化不能把标签对应到另一颗；10×121 压缩输出若以后采用，必须保存该局面的排序和逆映射。
- 只允许在完全没有合法动作时开放专用 pass ID。终局不再请求动作。模型只提供合法动作先验，任何错误、超时或非有限输出均回退现有合法搜索。
- 状态保存完整棋盘、双方座位、轮到谁、规则、ply、重复计数表、最近棋盘／走法、实际结果及模型哈希。以当前行棋方为统一朝向的 180° 变换必须同时变换棋子、营地、动作和历史。
- 网络输入使用自己的棋子／对方棋子／空位、双方起营和目标营、相对轴坐标、规则与当前重复计数、最近四个棋盘。完整 `seen_counts` 仍由搜索和裁判读取；有限历史平面不能完全表示所有重复历史，模型价值允许是近似值。缓存和数据去重不能把同棋盘不同历史的终局语义合并。

## 4. 小网络与真正学习的标签

建议先原创实现 `StarhopPV-small-v1`，不要从无许可仓库复制模型代码：121 个节点，64 通道，6 个带六方向邻接的残差消息层，加入池化后的全局信息。目标约 0.25–0.5M 参数，FP32 权重约 1–2 MB；这是设计预算，实际参数量以实现统计为准。

**策略头**根据源点、终点嵌入和相对位移计算关联分数，例如 `u(h_from) + v(h_to) + Q(h_from)·K(h_to)`，然后对全部合法端点做一次归一化。比相互独立的“从哪里”和“到哪里”更能表示不同源点的路线。策略网络优先用于排序，不因低概率永久删除合法走法。

**价值头**输出当前行棋方的胜／和／负三类概率，主标签来自完整双边对局的实际终局：胜 +1、和 0、负 −1。不能以距离差、入营数或现有 heuristic 分数代替结果。概率是否可展示，要在从未训练的完整对局留出集测 Brier／交叉熵和可靠性曲线后决定。

**辅助头**可低权重学习“每子现在能否一手进营”和真实完整连跳的最大推进；这些标签可以精确由规则计算。冻结残局的最短步数只在 `solved && proven` 的对应冻结任务学习，并带明确任务标志和掩码，未知样本不补零。辅助任务帮助表达运输，不凌驾真实胜负。

PUCT 搜索保存每个合法端点的访问数，训练策略目标为完整轮次的访问分布。初始配置可用 32 次模拟做流水线试验，再实测 64／128 次模拟和批量叶子推理。所有合法根着都有非零最低先验；噪声只用于训练开局，正式验收关闭。终局判断由规则层完成，价值以轮到谁视角转换回传。

初版损失可用策略交叉熵 + 价值三分类交叉熵 + 0.1×辅助损失 + 权重正则；采用 AdamW，固定种子，记录学习率与所有配置。比例只是起点，参数选择只看开发组。训练时保存 optimizer、模型、随机状态、缓冲区清单和阶段计数，能够断点复现。

## 5. 数据分阶段，明确防止泄漏

### 阶段 A：管线试验和暖启动

先产生 16 局完整合法轨迹，验证编码→动作 ID→掩码→规则回放→结果方向。随后使用 256 局混合教师对战，教师来自固定旧版本和开发候选，可包含随机合法开局。训练样本保存教师实际选择，标为 `behavior_clone`；价值标签仍用完整实际结果。

Fast PVS 根候选里包含 `upper` 分数，展示又只保留前五；**不能将这些不同性质的分数直接 softmax 成所有根着的真值分布**。暖启动可用实际选择的一热标签，但只用于减少随机乱走。仅模仿现有弱教师不证明棋力提高，也不能把这一步称为强化学习。

### 阶段 B：带搜索改进的自战

完成初始加载与延迟验证后，用当前网络 + PUCT 生成真实访问数；先做 512 局小迭代，失败或循环也保留。保存历代冻结模型和两种固定基线作为对手池，约 25% 的对局使用冻结对手，避免只对付自己。每轮重新评测后才决定是否替换训练冠军；“训练冠军”只是版本池中的模型，不是人类冠军称号。

后续按实际吞吐量扩为每轮 2,000–5,000 局，缓冲区采用最近若干轮加少量旧样本。每个模型的实际生成局数、总状态数、重分析数、梯度步数和失败数都写清；“重复训练一个状态十次”不计十个新局面。

### 拆分与留出

1. 按**完整对局和开局族**分组，建议训练／开发／最终留出 80%／10%／10%。同一局各手不得随机散入不同集合。同一开局交换颜色、镜像和旋转的所有样本归同一组。
2. 为每个开局生成规范化前缀哈希；如采用从中局起局，整条来源轨迹及近重复局面也留在同组。共享的标准初始局面不可避免，应从离线局面预测指标中单独剔除或报告，不能靠重复起局提高所谓测试准确率。
3. 每次训练生成数据先按开局族确定 split，再做增强。检索规范化棋盘＋轮到谁＋规则＋相关历史指纹跨集碰撞；碰撞按整局归组或从开发／测试指标剔除，不能只去掉某一手来隐藏轨迹重叠。
4. 两盘 178 手的大师原始记录，以及本次用户 95 手，已被人工和程序分析，属于**诊断／开发资料**。不能把已据此改特征的数据重新称为未见最终测试集。未经大师明确最优讲解的实际落子不是“最佳着”标签；原比赛和棋不能改为当前规则胜局训练结果。
5. 最终验收开局在模型与参数冻结后才生成或解封，不按失败结果挑掉局。运行一次后这一组即成为历史证据，下一轮候选另用新的封存组；公开每次被否决结果。
6. 时间截断或工程故障的棋谱标记 `censored`，不当真实和棋训练价值。只有按正式三次重复／600 手规则得到的和棋才能作为 z=0。未知冻结最短步差保留 null。

数据 schema 至少包含 `gameId, openingFamily, split, rulesId, source, engineHashes, modelHash, board, turn, seenCounts, legalIds, visits, chosenId, result, terminationReason, ownTurnCounts, wallTimeMs`。每局哈希、来源许可和数据生成配置随模型发布；不复制视频位图、收费开局库或未授权模型输出作公开训练数据。

## 6. 计算成本：先量吞吐，不承诺半小时练成

当前 C 350ms 八局公开记录的终局长度为 93、90、111、119、103、103、86、90 手，均值约 99 手；这是现有引擎比赛长度，**不是新网络自战吞吐测量**。训练预算可先保守按 100–130 手／局估算。

| 串行每手搜索预算 | 256 局数据生成的搜索时间估算 | 2,000 局估算 |
|---|---:|---:|
| 100ms | 43–56 分钟 | 5.6–7.2 小时 |
| 350ms | 2.5–3.2 小时 | 19.4–25.3 小时 |

估算为 `局数 × 每局手数 × 每手预算`，尚未计入环境通信、推理、优化、较长和棋、评测和故障重试；不当工期承诺。并发倍数不等于加速倍数，竞争同一 CPU 还会破坏等时评测。

正式大跑前在独立时段实测：200 个不同局面、预热后 batch 1／8／32 的前向 P50/P95、节点每秒、完整每手 P95、内存峰值、实际局长和有效训练状态每小时。CPU 推理目标先争取单次 batch1 P95≤10ms，但未实现前不声称达成。若太慢，减小网络或先用策略排序＋少量叶子价值；若更快，才增加模拟数。GPU 可加速训练与批量推理，但必须记录实际硬件，不借用其他项目的 GPU 毫秒数当本机结果。

初版推理优先本机辅助服务批处理，接口返回合法端点、模型哈希和真实耗时；再导出 ONNX 做浏览器 Worker 内的 WASM/WebGPU 验证。网络初始化一次、树复用必须核对历史和规则；下载、冷启动及最终规则校验的端到端耗时另外测。离线训练与正式等时比赛不同时争用同一计算资源。

## 7. 验收门槛与权重交付

发布棋力门槛沿用 `docs/benchmarks/STEP_ACCEPTANCE.md` 的最新要求：**稳定领先固定旧版至少五个自方完整回合**。之前研究报告的 `>2` 字段只是旧记录，不能据其称达到新要求。

1. **先通过规则与模型一致性。** 多阶段真实／随机合法局面：掩码和共享规则完全一致、棋子数不变、输入不变、立即获胜可选、长链只算一手、源点离开后为空、goalLock 逐落点限制正确；模型未训练和训练后都需做。
2. **模型确实学习且可以重载。** 训练／开发损失分开，训练状态清单可核对；新进程重载哈希相同权重后输出一致，ONNX 与训练框架结果在声明误差内一致。随机初始化、仅改常数或下载空文件不能称模型升级。
3. **同规则、同设备、同预算、配对开局。** 固定旧内核快照与模型各 350ms，交换先后手；每手从整段响应开始计时，推理算入预算，不给网络额外 GPU 时间却把旧版限制 CPU。双方若用不同硬件，应单独注明，不能称纯算法等时优势。报告 P50/P95/最大时延、冷启动、非法动作与回退率。
4. **八局门槛先不靠均值掩盖失败。** 至少四个独立开局各交换先后手，共八局，逐局报告胜负与最短冻结完成步差。保守发布门槛要求八局均获胜且已证明步差≥+5；未知、和棋、败局或小步差均不算通过。之后用更多封存开局确认，至少再做 100 局，并完整报告胜率置信区间、≥5 步占比、每个开局配对结果和未知比例；不能只取获胜或已解算子集。
5. **精确冻结运输与实际续走分列。** 仅 `solve(...).solved && proven` 给精确步差；超限保留未知，可另分配同样的离线求解预算扩展。策略续走反映版本收官表现，不能替代最短证明。这个指标评价特定已结束局面的运输，不证明此前整盘最优或冠军实力。
6. **人类挑战独立记录。** 用户及自愿高手实际多盘测试，保存规则、预算、设备、每手记录和完整败局。一次胜人、几盘胜旧版、和大师同着或训练池最高都不能转成人类 Elo、国家冠军胜率或“打遍天下”。

真正模型版本需要发布：`model.onnx` 或安全 tensor 权重、SHA256、输入/输出与坐标契约、完整许可证、训练配置、数据清单及拆分、训练日志、固定源码提交、等时验收棋谱、时延结果、适用规则与局限。项目生成的原创代码／权重可采用明确的 MIT 许可，但所有训练数据和第三方依赖仍须逐项记录来源。

阶段未通过时交付实际检查结果及研究版模型，不替换正式默认引擎、不把名称或界面评分改高。达到模型可运行、训练可复现、严格留出强于旧版三项之后，才进入发布流程；是否能对抗顶级人类仍需要另外验证。
